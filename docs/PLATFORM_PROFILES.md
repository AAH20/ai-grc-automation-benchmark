# Platform evaluation boundaries

GRCBench can evaluate product categories and named platforms only under authorized, reproducible conditions.

| Category | What can be tested | Frequent trade-off to expose |
|---|---|---|
| Compliance automation SaaS | integrations, tests, exports, APIs, workflows | breadth versus transparency and portability |
| Enterprise IRM/GRC | entity model, issue lifecycle, AI workflows, approvals | configurability versus implementation effort |
| Open-source GRC | framework portability, APIs, self-hosting, evidence model | control versus operational ownership |
| n8n | flexible workflow logic, self-hosting, AI nodes, retries | flexibility versus engineering and security burden |
| Zapier | rapid app connectivity, triggers, tasks, replay | ease versus task economics, throttling, and one-way flows |
| Custom Python | deterministic logic, tests, full provenance | engineering ownership versus product convenience |

## Initial named profiles

Potential comparison profiles include Vanta, Drata, Secureframe, Sprinto, Thoropass, Hyperproof, ServiceNow IRM, AuditBoard, OneTrust, Archer, CISO Assistant, Eramba, and GovReady-Q.

Inclusion is not endorsement. A documentation profile records only dated, primary-source claims and explicit limitations. It receives no numeric score. A verified profile requires an authorized tenant, retained redacted artifacts, exact benchmark version, and reproducible result.

## Workflow platforms

n8n and Zapier are evaluated as orchestration paths, not GRC systems. A successful execution does not prove control satisfaction. Their outputs must pass the same qualification gates as native integrations and custom code.
